## 后端模块依赖

```
┌─────────────────────────────────────────────────────┐
│                   admin-server                      │

┌─────────────────────────────────────────────────────┐

└───────────────────────┬─────────────────────────────┘
```

### 依赖方向说明

| 模块 | 依赖的模块 | 说明 |
|------|-----------|------|
| admin-server | admin-system | 启动入口，注入业务Bean |
| admin-system | admin-framework | 使用框架配置的基础能力 |
| admin-framework | admin-common | 使用统一响应和异常类 |
| admin-common | 无 | 最底层，纯POJO |

## 内部模块调用约定

### 后端分层调用规范

```
Controller → Service → Mapper → Database
    │            │           │
    │            │           └─ BaseMapper<T> 基础CRUD
    │            │           └─ 自定义@Select注解SQL
    │            │
    │            └─ IService<T> 基础Service
    │            └─ 业务Service实现（@Service）
    │            └─ Support辅助类（复杂逻辑拆分）
    │
    └─ @RestController
    └─ 返回 ApiResult<T>
```

**调用规则**：
- Controller只做参数校验和响应封装，不包含业务逻辑
- Service层处理核心业务逻辑，可调用其他Service
- Mapper层只做数据访问，不包含业务逻辑
- Support类用于复杂业务逻辑的辅助拆分，被Service调用

### 前端组件调用规范

```
Views (页面)
  ├── Layouts (布局)
  ├── Components (业务组件)
  │     └── Sub-components (子组件)
  ├── Composables (组合式函数)
  ├── Stores (状态管理)
  └── Utils (工具函数)
```

**数据流方向**：单向数据流，Props向下传递，Events向上冒泡
