Large Languaue Model：大语言模型 --> 大模型


对于大语言模型来说，它只认识数字而不认识文本，所以文本的输入输出，都是会转换为数字串来进行传输的。

Input 和 Output：都是多维数字（数字数组）

2.1 编码

2.1.1 切分

  • 将一段文本根据一定的切分规则，切分为多个Token。

2.1.2 映射

  • 每个Token对应一个Token ID，也就是说，每一段文本最后都会被转换成为一个数字数组。

2.2 解码

解码只有映射步骤，因为大语言模型返回的是一个个Token，而不是一整段文本。

2.2.1 映射

解码时候的映射是从Token ID 转换为 Token，是反方向地转换。

2.3 Token和词

Token和词并不是一一对应。

主要看数据的培训以及大模型自身的切分规则。

1个Token：

  • 0.75个英文单词
  • 1.5 - 2个中文汉字

3 Context

上下文：携带聊天的历史记录以及工具等内容。

Context：大模型每次处理任务时所接收到的信息总和：

  • 历史记录
  • 当前问题 UserPrompt
  • 系统角色预设 SystemPrompt
  • 当前回答（Token追加） AssistantPrompt
  • 工具列表

4 ContextWindow

上下文窗口：Context所能容纳的Token数量

以下为主流的大模型的ContextWindow大小：

GPT-5.4105万
Gemini 3.1pro100万
Claude Opus 4.6 100万

5 Prompt

提示词：大模型接收和反馈的具体问题、答案或指令

Prompt越清晰，则大模型的输出质量越高。

5.1 Prompt Engineering

提示词工程的出现，是为了培训让Prompt提示词的质量更高，但随着大语言模型的能力的提升，Prompt的要求已经不再那么必要，并且Prompt Engineering的门槛比较低，其本质是只是为了让提问更加清晰。所以目前的Prompt Enginerring已经不是那么重要了，提到的也是寥寥无几。

5.2 Prompt的种类

主要的有3种，有些框架会配置4种，即多加了一个Tool Prompt。

  • User Prompt：具体任务。由用户输入，为用户向大模型提出的问题或指令。
  • System Prompt：人设和做事规则。由开发者在后台配置，它更是某一次对话的约束和角色的预设，让大模型能按照我们的约定生成更符合我们要求的内容。
  • Assistant Prompt：回复内容。由大模型对用户的问题进行回答。

6 Tool

Tool是大模型与外界数据、环境等的桥梁，大模型通过Tool来实现获取外界信息。

6.1 查天气案例

Tool会去请求外部的例如气象台接口，从而获取到实时的真实数据，而返回给用户的，是由大模型对实时数据经过组织后的结果。

大模型并不能直接调用工具，它的职责其实是根据平台提供的可用工具列表，并且根据user prompt，来选择需要执行的工具，让平台去调用工具指令，将工具返回的真实数据再交给大模型去组织人性化语言。

注意，真正调用工具的是平台。

6.2 各个角色的职责

6.2.1 大模型

  • 选择工具：在平台提供的工具列表中，选择需要调用的工具
  • 归纳总结：对平台发送返回的工具调用结果，进行整理归纳总结，并输出人性化的结果

6.2.2 平台

平台是协调各方交流的桥梁，也是真正执行工具调用的角色

6.2.3 工具

工具会去执行本地指令，或者去调用外部的接口来获取一些实时或者是私有的数据内容

6.2.4 用户

用户是发起者，向平台请求某个执行或咨询某个问题，并且获得某个答复

7 MCP

Model Context Protocol：MCP是一种协议，用于规范应用程序中的大模型，与外部接口之间的调用。

MCP的最终目的和Tool是一致的，都是为了给大模型应用附加对外的能力，例如获取实时数据，获取私有、专业的数据等。

7.1 Tool的现有问题

  • ChatGPT：OpenAI规范
  • Claude：Anthropic规范
  • Gemini：Google规范

问题：对于同一套工具，为了对接不同的大模型，需要实现多套工具代码。

解决：建立标准（MCP），统一的工具接入规范。

8 Agent

Agent智能体必须满足两个条件：

  • 自主规划
  • 自行调用工具

当前主流的Agent：

  • Claude Code
  • Codex
  • Gemini CLI

市场上这些主流的Agent，其构建模式也不尽相同：

  • ReAct
  • Plan And Execute

9 Agent Skill

Agent Skill 相当于给Agent一份说明文档（markdown），限制Agent的一些行为。

9.1 案例 -- 出门小助手

如果我们希望我们提出的问题，是有前置条件的，如上面的“出门习惯”，而得到的答复也有格式要求，如上面的“输出格式”，那么我们需要在每次咨询大模型的时候，都将以上的要求先作为system prompt，配合我们的问题，再发送给大模型。

每次都携带这个内容无疑是相当冗长的。

这就是Agent Skill要做的事情，先给Agent设定好要求，再对其进行咨询，则Agent的每次思考和回答，都会按照我们的要求来执行。

9.2 文档格式

-------（元数据层，必须存在，Agent是通过元数据层的信息来寻找的）

name: Agent Skill的名称（例如 go-out-checklist）
description: Agent Skill的描述
-------
（指令层，格式并不做要求，只要能向Agent说明即可）

一般：
1、目标
2、执行步骤
3、判断规则
4、输出格式
5、示例

9.3 定义完存入磁盘

例如在claude中

cd ~/.claude/skills
mkdir go-out-checklist          // 这里的文件夹名称要和Agent Skill 的name对应
vim SKILL.md                    // 这里的SKILL.md文件名称是固定的，且为大写
                                // 将Agent Skill的内容复制到SILL.md文件中
